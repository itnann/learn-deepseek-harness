# 讲解规范

这份规范是本仓库后续章节的写作约定。目标读者是能看懂基础 Python/JavaScript，但对 Harness 架构、事件溯源、依赖注入和插件生命周期不熟悉的人。

`course/` 是逐章演进、代码可运行的学习主线；`lessons/` 是读完主线后的设计手册；`docs/` 是源码证据与延伸资料，只负责验证结论，不负责带领读者逐文件阅读。

## 学习 learn-claude-code 的哪些部分

`learn-claude-code` 最值得沿用的不是措辞，而是它控制认知负担的方式：

1. 每章只解决一个核心问题。
2. 开头先给一句格言和所属 Harness 层。
3. 先讲为什么需要这个机制，再展示源码。
4. 用一张总览图建立位置感。
5. 只截最小代码骨架，复杂分支折叠到“深入源码”。
6. 用“相对上一章的变化”固定读者的已有认知。
7. 结尾给可执行的观察任务，并自然引向下一章。

DeepSeek Harness 本身不是渐进式教学脚本，所以本仓库不按源码目录拆课，而是构造一套连续的教学实现。三类材料互相支撑：

- 可运行课程：每章先制造一个真实压力，只增加一个机制，并保留上一章心智模型。
- 设计手册：跨章节总结收益、代价和采用时机。
- 源码证据：需要验证时，再说明这个思想在插件、service、event 和配置层怎样落地。

## 每章固定结构

```text
# 编号. 主题

> 一句话格言
> Harness 层：这一章解决什么责任

## 先看结论
## 问题：没有它会怎样
## 全局视角（配图）
## 最小模型（伪代码）
## 设计答案与核心不变量
## 收益、代价与过度设计风险
## 怎样在自己的项目里逐步借鉴
## 与 learn-claude-code / Claude Code 的产品哲学对照
## 容易误解的地方
## 动手验证
## 下一章
## 证据与深入源码（可选）
```

不是每章都必须逐字使用这些标题，但阅读节奏保持一致：先建立模型，再进入实现，最后验证。

## 证据标签

涉及比较时使用三种标签：

| 标签 | 含义 | 可以下什么结论 |
|---|---|---|
| `源码事实` | 能在当前固定提交的实现或测试中直接定位 | 可以描述具体数据结构、调用顺序和失败语义 |
| `公开事实` | 能在官方公开仓库的 README、配置、插件或 CHANGELOG 中定位 | 可以描述产品表面和扩展协议，不能断言内部算法 |
| `教学类比` | 来自 `learn-claude-code` 的简化实现或“深入 CC 源码”说明 | 用来帮助理解；未在本地官方源码复核时不能升级为官方实现事实 |

如果只有行为现象，没有源码或协议证据，写“当前无法从本地材料确认”，不要用“显然内部采用了……”补空白。

## 代码引用原则

- 课程正文只在结论需要验证时引用源码，不用调用链充当文章结构。
- 源码链接固定到提交哈希，避免主分支变化导致行文失效。
- 优先引用入口函数、核心类型和测试，避免把整文件贴进文章。
- 代码片段通常不超过 25 行；超过时先改写成伪代码，再给源码链接。
- 区分 TypeScript 类型约束与运行时检查。接口里写了不等于外部输入已经校验。
- 配置参与运行时装配时，必须同时引用 `cordis.patch.yml`，不能只看 `.ts` 文件。

## 配图原则

- 一张图只表达一个主要关系：调用顺序、分层、状态变化或对比。
- 图标题说“它是什么”，图下注释说“应该看哪里”。
- 蓝色表示模型请求主线，橙色表示工具/外部行动，绿色表示持久化事实，紫色表示插件扩展点。
- SVG 必须包含 `<title>` 和 `<desc>`；正文仍提供文字版读图说明，不能让颜色成为唯一信息。
- 复杂时序优先 Mermaid；需要稳定排版、卡片和注释时使用 SVG。

## 术语口径

| 英文 | 本仓库写法 | 首次出现时的解释 |
|---|---|---|
| harness | Harness / 智能体运行框架 | 模型之外，负责上下文、工具、权限和生命周期的系统 |
| agent loop | Agent Loop | 模型请求、工具执行、结果回填形成的循环 |
| session log | Session 事件日志 | 只追加、可重放的会话事实序列 |
| surface | 模型消息面 | 从完整事件日志投影出的当前模型可见历史 |
| service | Service / 服务能力 | 通过 Cordis Context 暴露的稳定能力接口 |
| provider | Provider / 实现方 | 某个 Service 的具体本地、远程或第三方实现 |
| consumer | Consumer / 使用方 | 调用 Service 的插件，常见形式是模型工具 |
| waterfall | Waterfall / 瀑布式中间件 | 必须调用 `next()` 才会继续向下游委托的拦截链 |
| scope | Agent 作用域 | 把工具、提示词和监听器贡献限制到某个 Agent |

## 完成标准

一章交付前至少自查：

- 初学者能否先用一句话复述机制？
- 读者是否先理解了问题、设计收益和成本，而不是先看到文件名？
- 需要验证的关键结论能否回到固定版本的文件、测试或公开材料？
- 是否混淆了 DeepSeek 源码、Claude 官方公开仓库和教学复刻？
- 图和正文能否独立表达同一件事？
- 是否给出了一个不需要 API Key 的静态验证动作，或清楚标注了运行实验的前置条件？
